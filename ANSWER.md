# Задание 2. Теоретическое задание: параллелизуемость/code divergence/memory coalesced access
**1)** Пусть на вход дан сигнал x[n], а на выход нужно дать два сигнала y1[n] и y2[n]:

```
 y1[n] = x[n - 1] + x[n] + x[n + 1]
 y2[n] = y2[n - 2] + y2[n - 1] + x[n]
```

Какой из двух сигналов будет проще и быстрее реализовать в модели массового параллелизма на GPU и почему?

Для вычисления y1[n] значения x[n-1], x[n], x[n+1] могут быть считаны независимо для каждого n. 
Нет зависимостей между элементами y1[n] для разных n.
Каждый элемент y1[n] может быть вычислен независимо от других. 
Если x[n] хранится в памяти как линейный массив, доступ к x[n-1], x[n], x[n+1]
будет соседним для соседних потоков, что обеспечивает эффективный доступ к памяти.
Для вычисления y2[n] требуется знать y2[n-2] и y2[n-1].
Это создает последовательную зависимость, так как вычисление y2[n] невозможно, пока не вычислены y2[n-2]
и y2[n-1]. Параллелизм затруднен из-за последовательных зависимостей. 
Доступ к x[n] может быть эффективным, но доступ к y2[n-2] и y2[n-1] зависит от последовательности вычислений, что затрудняет эффективное использование памяти.
Сигнал y1[n]  проще и быстрее реализовать в модели массового параллелизма на GPU.

**2)** Предположим что размер warp/wavefront равен 32 и рабочая группа делится
 на warp/wavefront-ы таким образом что внутри warp/wavefront
 номер WorkItem по оси x меняется чаще всего, затем по оси y и затем по оси z.

Напоминание: инструкция исполняется (пусть и отмаскированно) в каждом потоке warp/wavefront если хотя бы один поток выполняет эту инструкцию неотмаскированно. Если не все потоки выполняют эту инструкцию неотмаскированно - происходит т.н. code divergence.

Пусть размер рабочей группы (32, 32, 1)

```
int idx = get_local_id(1) + get_local_size(1) * get_local_id(0);
if (idx % 32 < 16)
    foo();
else
    bar();
```

Произойдет ли code divergence? Почему?
Формула для idx:

idx=get_local_id(1)+32*get_local_id(0)
get_local_id(1) изменяется быстрее чем get_local_id(0) так как x-координата изменяется чаще всего внутри warp.
Значения idx в пределах одного warp (где get_local_id(0) фиксировано)будут равны idx=k⋅32+i,i∈[0,31]
Один warp содержит 32 потока, и их idx%32 принимает значения от 0 до 31.
Половина потоков warp (0≤idx%32<16) будет выполнять foo(), а другая половина (16≤idx%32<32) — bar()
Инструкции внутри if и else различаются, поэтому потоки в warp разделяются на две группы:
Первая группа исполняет foo().
Вторая группа исполняет bar().
Поскольку все потоки одного warp должны завершить исполнение инструкции, потоки, исполняющие foo(), будут ждать, пока потоки, исполняющие bar(), завершат, и наоборот.
Это приводит к code divergence.

**3)** Как и в прошлом задании предположим что размер warp/wavefront равен 32 и рабочая группа делится
 на warp/wavefront-ы таким образом что внутри warp/wavefront
 номер WorkItem по оси x меняется чаще всего, затем по оси y и затем по оси z.

Пусть размер рабочей группы (32, 32, 1).
Пусть data - указатель на массив float-данных в глобальной видеопамяти идеально выравненный (выравнен по 128 байтам, т.е. data % 128 == 0). И пусть размер кеш линии - 128 байт.

(a)
```
data[get_local_id(0) + get_local_size(0) * get_local_id(1)] = 1.0f;
```

Будет ли данное обращение к памяти coalesced? Сколько кеш линий записей произойдет в одной рабочей группе?

Все потоки warp обращаются к последовательным элементам массива (индексы идут подряд).
Память coalesced: доступы укладываются в одну кеш-линию (каждая кеш-линия покрывает 32 элементов float).
Кеш-линии на группу:
Группа (32, 32, 1) содержит 32*32=1024 потоков.
Индексы потоков распределяются по строкам размера 32, каждая строка укладывается в одну кеш-линию.
Всего записей 32 кеш-линий по одной на каждую строку.
Память coalesced: да.
Кеш-линий: 32.

(b)
```
data[get_local_id(1) + get_local_size(1) * get_local_id(0)] = 1.0f;
```

Будет ли данное обращение к памяти coalesced? Сколько кеш линий записей произойдет в одной рабочей группе?
Индексы get_local_id(1) в пределах одного warp изменяются от 0 до 31. Таким образом, потоки одного warp обращаются к последовательным адресам памяти.
Однако get_local_id(0) изменяется с шагом 32, что приводит к скачкам индексов по строкам.
Память coalesced: доступы будут coalesced только внутри warp, но между warp-ами возможны разрывы.
Кеш-линии на группу:
Каждый warp укладывается в одну кеш-линию (по 32 элемента).
32 warp-ов укладываются в 32 кеш-линий.
Память coalesced: частично внутри warp.
Кеш-линий: 32
(c)
```
data[1 + get_local_id(0) + get_local_size(0) * get_local_id(1)] = 1.0f;
```

Будет ли данное обращение к памяти coalesced? Сколько кеш линий записей произойдет в одной рабочей группе?

Смещение на 1 приводит к сдвигу всех обращений на один элемент.
Первый элемент каждого warp оказывается на границе кеш-линии:
Вместо [0,31] потоков warp теперь обращаются к [1,32].
Память не coalesced: каждый warp теперь использует две кеш-линии.
Кеш-линии на группу:
32 warp-ов, каждый использует 2 кеш-линии.
Всего  32*2=64 кеш-линий.
Память coalesced: нет.
Кеш-линий: 64.
